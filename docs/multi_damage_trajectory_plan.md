# Multi-Damage Trajectory Plot: GNN vs Backprop Comparison

## Goal

Produce a trajectory figure showing **repeated damage → recovery cycles** for
both the GNN (self-attention) model and a backprop baseline, plotted on the
same axes for direct comparison.  Each cycle consists of:

1. Inject reversible damage (40 gates, shotgun mode, **ko_out** / unseen patterns).
2. Let the method recover.
3. When accuracy returns to a **threshold**, apply the next damage event.

**Source of GNN truth: `eval_type=ko_out` only.** In-distribution (`ko_in`)
trajectories from the vocabulary are out of scope for this comparison. Training
still logs both; readers of `stepwise_metrics.jsonl` should filter with
`eval_type=ko_out`.

**Flagship setting:** `damage_injection_mode: threshold_reinject` for **both**
the periodic GNN evaluator and the post-hoc BP loop in
`experiments/bp_multi_damage_trajectory.py`. Fixed-interval `multi` remains
available for ablations, but plots and sweeps should default to threshold logic.

**Matched statistics:** **256** parallel trajectories (same as
`eval.periodic_eval_batch_size`), horizon **250** steps (same as
`eval.periodic_eval_inner_steps`). We do **not** require bit-identical damage
patterns between GNN and BP; i.i.d. shotgun draws per injection are enough for
the distribution to be representative at this batch size.

The figure is intended as an expansion of Panel C in the combined three-panel
figure generated by `experiments/combined_damage_stepwise_plot.py`.

**Backprop in scope.** The GNN side comes from training (`stepwise_metrics.jsonl`,
ko_out). The BP side comes from **post-hoc** runs of `bp_multi_damage_trajectory.py`
after training, using the same run’s config and threshold hyperparameters. Today,
`train.py` with `backprop.enabled` still runs vocabulary BP
(`_run_backpropagation_training_with_knockouts`)—one fixed knockout per vocab
slot—which is **not** this multi-damage schedule; that path is unrelated to the
joint ko_out trajectory plot.

## Vision: post-hoc BP matching + joint plot (ko_out, threshold)

### Workflow (high level)

1. **Train** with `eval.knockout_eval.damage_injection_mode: threshold_reinject`
   and the desired `reinject_threshold` / `reinject_cooldown_steps` (e.g. 0.99 / 25
   to mirror the old fixed-interval spacing `greedy_injection_recover_steps: 25`).
2. **Record** GNN ko_out stepwise metrics (`periodic_eval_log_stepwise: true`) under `results/metrics/**/run_<id>/stepwise_metrics.jsonl`.
3. **After training**, run `experiments/bp_multi_damage_trajectory.py` with the same
   run’s W&B `run_id` (or local resolved config), **256** circuits, **`--bp-epochs 250`**,
   and matching threshold flags (`--damage-injection-mode threshold_reinject`,
   `--reinject-threshold`, `--reinject-cooldown-steps`, same `damage_start_offset`,
   `max_damage_per_circuit`, `damage_prob`, `reversible-bias`).
4. **Plot GNN** with `experiments/visualization/plot_stepwise_metrics.py`:
   pass `eval_type=ko_out` and the desired `epoch` (or use latest). This script
   already defines the visual language (e.g. unseen color `#34b779`, band alpha,
   `--accuracy-only` layout).
5. **Joint figure:** extend or wrap the stepwise plotter so the **same axes**
   add one BP curve + band (mean ± std over 256 circuits), reusing **identical**
   styling parameters from `plot_stepwise_metrics.py` for the GNN series. Do **not**
   redesign the GNN layer; only add a second series (and legend) matched to that design. A minimal approach is to load BP aggregates (CSV or in-memory DataFrame)
   and plot with a distinct color (e.g. reuse the BP blue from
   `plot_multi_damage_trajectory` in `bp_multi_damage_trajectory.py`, or define one
   shared palette next to the constants in `plot_stepwise_metrics.py`).

### Ensuring the BP script rebuilds the same **preconfigured** circuit as training

Training (`train_loop.py`, repair mode) calls `preconfigure_circuit_logits` with:

- `wiring_key = wiring_fixed_key` (same PRNG key derived from `test_seed` in `train.py`),
- `steps = preconfig_steps`, `lr = preconfig_lr` (from `train_model`: `backprop.epochs`,
  `backprop.learning_rate`),
- **`optimizer`, `weight_decay`, `beta1`, `beta2`** from `backprop_config`.

`experiments/bp_multi_damage_trajectory._create_baseline` currently passes only
`steps`, `lr`, and wiring key into `preconfigure_circuit_logits`; it does **not**
forward optimizer / WD / betas from `cfg["backprop"]`. For a numerically aligned
baseline, **`_create_baseline` should be updated** to mirror the `train_loop`
call (same arguments as the block around `preconfigure_circuit_logits` in
`train_loop.py`). Until then, expect small drift versus the training baseline.

**Config on disk:** Prefer the **resolved** snapshot written with metrics
(`results/metrics/.../config_resolved.yaml`) so `circuit.layer_sizes`, `training`,
`backprop`, and `test_seed` match the run. If loading from W&B JSON, normalize
nested keys: training uses **`backprop.epochs` / `backprop.learning_rate`** as
preconfig step count and LR, not necessarily top-level `preconfig_steps` /
`preconfig_lr`. The BP script should read **`cfg["backprop"]`** for preconfig
parity when extending `_create_baseline`.

**Sanity check:** After preconfig, evaluate hard accuracy on the full task; it
should be at or near 1.0 before any damage (same expectation as training).

## Why threshold-triggered reinjection?

The current `damage_injection_mode="multi"` uses a **fixed interval** between
damage events (`greedy_injection_recover_steps`).  This creates an unfair
comparison because:

- **GNN** recovers in ~2–3 message steps after a 40-gate reversible hit.
- **BP** needs ~25+ gradient steps to recover from the same hit.

With a fixed interval (e.g. 25 steps), the GNN spends most of its time
sitting at 100 % accuracy doing nothing, while BP is still climbing.  The plot
looks misleading.

A **threshold-triggered** policy injects the next damage event only after the
method actually demonstrates recovery, making the visual comparison honest.

### Proposed policy: `threshold_reinject`

| Parameter | Default | Description |
|---|---|---|
| `reinject_threshold` | 1.0 | Hard accuracy that counts as "recovered" (values such as **0.99** avoid long plateaus just below 1.0 from float noise) |
| `reinject_cooldown_steps` | 5 | Extra **message / gradient** steps after recovery before the next damage (use **25** to match `greedy_injection_recover_steps` when comparing to legacy `multi` spacing) |
| `max_damage_per_circuit` | 9 | Cap on total damage events |
| `damage_start_offset` | 5 | Warm-up steps before first damage |

Injection rule (per circuit, evaluated every step):

```
recovered = (current_hard_accuracy >= reinject_threshold)
cooldown_elapsed = (steps_since_recovery >= reinject_cooldown_steps)
inject_now = recovered & cooldown_elapsed & (n_events < max_damage_per_circuit)
```

Because GNN recovers faster, it will accumulate more damage events in the same
number of steps, which is the honest outcome.

## Implementation plan

### 1. Evaluator: add `threshold_reinject` mode

**File:** `boolean_nca_cc/training/evaluation.py`, inside `_evaluate_loop`
(lines ~835–845).

Currently:

```python
steps_since_first_damage = step - per_circuit_offsets - 1
first_damage = (steps_since_first_damage == 0)
subsequent_damage = (steps_since_first_damage > 0) & (
    (steps_since_first_damage % (recover_steps + 1)) == 0
)
inject_now = first_damage | subsequent_damage
```

Add a branch **before** this block:

```python
if damage_injection_mode == "threshold_reinject":
    # Per-circuit tracking (initialised before the loop):
    #   recovered_at_step: jp.ndarray[batch_size] — step when threshold was reached
    #   cooldown_met: bool mask
    current_acc = <per-circuit hard accuracy from previous step>
    just_recovered = (current_acc >= reinject_threshold) & ~already_recovered
    recovered_at_step = jp.where(just_recovered, step, recovered_at_step)
    cooldown_met = (step - recovered_at_step) >= reinject_cooldown_steps
    inject_now = cooldown_met & (eval_perturb_counter < max_damage_per_circuit)
    # Reset tracking after injection
    ...
```

Key detail: the per-circuit accuracy needed for the threshold check is already
computed at the end of each step (it is `hard_accuracy` from `vmap_get_loss`).
Store it in a running variable.

New function-level parameters:

```python
reinject_threshold: float = 1.0,
reinject_cooldown_steps: int = 5,
```

These are only used when `damage_injection_mode == "threshold_reinject"`.
Existing modes remain unchanged.

### 2. BP loop: add matching threshold policy

**File:** `experiments/bp_multi_damage_trajectory.py`, inside
`run_bp_multi_damage`.

Replace the fixed `injection_set` lookup with per-circuit state tracking:

```python
recovered = False
cooldown_counter = 0
events = 0

for step_count in range(bp_epochs):
    # Check injection
    if step_count == damage_start_offset and events == 0:
        inject = True  # first damage
    elif recovered and cooldown_counter >= reinject_cooldown_steps and events < max_events:
        inject = True
    else:
        inject = False

    if inject:
        events += 1
        recovered = False
        cooldown_counter = 0
        # generate & apply pattern ...

    # After train_step, check recovery
    acc = step_aux["hard_accuracy"]
    if acc >= reinject_threshold:
        if not recovered:
            recovered = True
            cooldown_counter = 0
        else:
            cooldown_counter += 1
```

Because BP runs are sequential (one circuit at a time), this is plain Python
with no JAX vectorisation needed.

## Implementation notes (2026-04-14)

### What was implemented

**`boolean_nca_cc/training/evaluation.py`** — GNN evaluator (`_evaluate_with_loop`):
- New params: `reinject_threshold: float = 1.0`, `reinject_cooldown_steps: int = 5`.
- Per-circuit JAX state: `prev_hard_accuracies`, `is_recovered` (bool mask),
  `recovered_at_step` (int array). Initialised before the loop; updated at the
  end of each step.
- Injection branch: first damage uses existing `per_circuit_offsets`;
  subsequent damage fires when `is_recovered & (step - recovered_at_step >= cooldown)`.
  After injection, `is_recovered` is reset to `False` for the injected circuits.
- The `can_inject_mask` cap (`eval_perturb_counter < max_damage_per_circuit`)
  still applies, so existing modes are unchanged.

**`experiments/bp_multi_damage_trajectory.py`** — BP loop + GNN runner + CLI:
- `run_bp_multi_damage`: plain-Python per-circuit state tracking
  (`events`, `is_recovered`, `cooldown_counter`). Patterns are generated
  on-the-fly at injection time rather than pre-computed.
- `run_gnn_multi_damage`: passes `damage_injection_mode`, `reinject_threshold`,
  `reinject_cooldown_steps` through to `evaluate_model_stepwise_batched`.
- CLI flags: `--damage-injection-mode {multi,threshold_reinject}`,
  `--reinject-threshold`, `--reinject-cooldown-steps`.

**`experiments/visualization/plot_trajectory_cli.py`**:
- `--damage-injection-mode` choices extended to `{single, multi, threshold_reinject}`.
- `--reinject-threshold` and `--reinject-cooldown-steps` flags added.

**`experiments/visualization/plot_trajectory.py`**:
- `plot_combined_bp_sa_stepwise_performance` accepts and forwards the two new
  params to all four `evaluate_circuits_in_chunks` call sites (ID, OOD × multi, static).

### Known issues / follow-ups

- **BP baseline vs training:** `_create_baseline` in `bp_multi_damage_trajectory.py`
  should pass the same `preconfigure_circuit_logits` kwargs as `train_loop.py`
  (`optimizer`, `weight_decay`, `beta1`, `beta2` from `backprop`) and resolve
  `preconfig_steps` / `lr` from `cfg["backprop"]` when W&B config has no flat
  `preconfig_*` keys (see Vision section).
- **GNN flatline at ~0.71**: The WandB artifact `best_model_eval_ko_hard_accuracy`
  was not found for run `2uoa076p`; the fallback `latest_checkpoint` (step 7217)
  is lower quality. Re-running with the correct artifact name
  (`best_model_eval_ko_in_hard_accuracy`) should fix this.
- **Baseline starts at 0.503**: The preconfigured circuit (200 steps, lr=1e-2)
  begins below 1.0.  BP recovers to 1.0 within ~175 gradient steps, but the
  first damage-recovery cycle is artificially slow.  Increasing `preconfig_steps`
  or `preconfig_lr` would give a cleaner baseline.
- **Threshold of exactly 1.0 is strict**: `hard_accuracy` is a float mean; some
  circuits plateau at 0.9999 for many steps before hitting 1.0.  A threshold of
  e.g. 0.999 would trigger reinjection sooner and produce more damage events
  within the same BP epoch budget.
